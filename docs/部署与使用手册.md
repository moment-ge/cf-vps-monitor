# 云端观测站部署与使用手册

版本 1.0.0 · 2026 年 9 月 5 日

本手册说明如何把监控面板部署到 Cloudflare 免费套餐，接入 Linux、Windows 和 macOS 节点，以及维护 20 台以上低配置 VPS。项目已经完成本地功能验证和跨平台编译；线上发布需要 Cloudflare 登录，真实 Linux 与 Windows 机器的运行验收仍需接入后完成。

## 1 交付内容与边界

| 路径 | 内容 |
| --- | --- |
| `src/` | React 监控页面和管理后台 |
| `worker/` | Cloudflare Workers API、鉴权与告警任务 |
| `migrations/` | D1 数据库结构 |
| `agent/` | Go 探针源码、配置样例和安装脚本 |
| `release/agent/` | 8 个平台架构的可执行文件和 SHA256SUMS |
| `tests/` | 本地 Workers 与 D1 集成测试 |
| `scripts/` | 开发、编译、演示、部署准备脚本 |
| `upstream/` | 已拉取的 Komari 和主题参考源码，本地保留 |
| `licenses/` | 复用资源及依赖许可 |

这是适合 Cloudflare 的独立实现，不是原版 Komari 换一个部署命令。原版 Komari 的 Go 常驻服务器和本地数据库不在 Cloudflare 免费 Workers 的运行模型内；本项目重新实现 API 与数据存储，使用自己的探针协议。页面参考原站多列节点卡片，采用纯 CSS 网格背景、分层监控台表面和可旋转的抽象节点球体；地球球面只表达区域分布，不表示真实地图或国界。

当前管理员可以增改节点、管理分组与显示顺序、隐藏节点、归档/恢复、重置探针密钥、记录费用与到期日期、设置监控阈值、查看告警和导出配置摘要。删除采用可恢复的归档方式，归档后拒绝新的探针上报，历史按保留规则清理。

没有实现远程 SSH、重启服务器、命令执行、文件管理、多管理员角色或对 3x-ui 的业务管理。探针不读取 3x-ui 数据库、账号、用户连接或订阅内容，不改变其配置，也不在节点上开放监听端口。

## 2 架构与低配置优化

数据路径为：节点探针通过 HTTPS 上报到 Workers，Workers 验证节点独立密钥，将最新指标写入 D1，并按采样周期保留历史。浏览器从 Workers 读取数据。Cloudflare 每 5 分钟执行一次告警检查和过期清理。

### 探针行为

- 单个 Go 可执行文件，无 Python、Node.js、Docker 或额外数据库运行时。
- `GOMAXPROCS=1`，Go 运行时内存软目标 24 MiB，GC 目标 50%。软目标不等于操作系统硬内存限制。
- 采样间隔内休眠；默认每 120 秒读取一次系统计数器。
- CPU 为两次采样之间的平均利用率，网速为网络计数器差值除以实际时间间隔。
- 只读系统汇总、一个磁盘路径和网卡计数器，不逐进程扫描。
- 系统与 CPU 型号只在启动时读取；HTTP 请求与响应均有超时和大小限制。
- 默认不做 TCP 探测。开启后，每 5 个上报周期做 3 次 TCP 握手尝试，每次最多 2 秒。
- 启动随机等待 1–30 秒，后续加入少量随机延迟，避免大量节点同时请求。
- 故障后指数退避，最长每小时重试。401 会退出，提示更新失效密钥；Linux/Windows 服务管理器有限重试，macOS LaunchAgent 每 300 秒至多重启一次。
- 成功上报不逐条写日志，失败只记首次和每 10 次重试，避免长期日志膨胀。

Linux systemd 单元设置了低优先级、CPUQuota=5%、MemoryMax=64M、禁止使用 swap 和最多 16 个任务。这些是保护上限，不代表探针平时占用这么多资源。极小或繁忙节点可将上报间隔提高到 300 秒。

### 页面与后端

- 每页渲染 20 台节点，列表和卡片视图可切换；一次拉取全量轻量节点摘要，20–100 台通常无需复杂服务端分页。
- 默认卡片视图，桌面最多四列，手机单列；页面背景由纯 CSS 网格和主题色面构成，不加载照片或壁纸资源。手机使用更不透明的卡面；支持浅色、深色和系统减少透明度偏好。
- 概览默认选中在线状态，地区球体自动旋转；用户可拖拽暂停、点击播放/暂停或复位，地区标记显示在线数/总数。
- 搜索、分组、状态筛选在浏览器内完成，不额外请求服务器。
- 只在打开一个节点详情时请求该节点历史，图表库独立加载。
- 每张历史图最多约 240 个样本，长时间范围选取时间桶最后一个已有样本。
- 概览与节点管理刷新周期至少 120 秒，跟随后端间隔；后台标签页暂停刷新，返回前台时更新。浏览器以服务器时间和本地单调计时推算样本年龄，每 15 秒检查过期状态，即使刷新失败也不会一直显示旧的在线状态。
- 节点接入弹窗单独每 10 秒检查该节点的首报，最多检查 10 分钟，隐藏标签页暂停，收到新样本即停止；不改变 VPS 采样频率。
- 历史按时间桶只存一个样本，避免每次上报都增加长期历史。
- SQL 使用参数绑定；历史主键为 `(node_id, ts)`，支持按节点和时间查找、清理。
- 历史另建时间索引，Cron 每次集中删除最多 500 个过期样本；事件和登录限流各清理最多 200 条，缩短保留期后会分轮清理积压。
- 告警按集合写入，事件与状态在同一事务提交。101 台同时告警或恢复时，未配置 Telegram 的单次维护仅需 7 条 SQL；配置 Telegram 后最多 13 条 SQL 和 5 次外部请求，低于免费调用限制。
- 创建、归档和恢复节点与活动节点数量更新在同一事务完成，避免规模保护使用过期数量。
- 公开响应不进入共享边缘缓存，避免节点隐藏或站点改为私有后缓存继续泄露数据。免费请求估算必须包含访客轮询。

### 指标含义

CPU 和网络速率显示区间平均值，不能用来复现秒级峰值。历史保存每个桶内第一个收到的样本，并用桶起点标记时间；长范围展示时选取更大桶中的最后一个历史样本，未做均值汇总。

磁盘默认是 Linux/macOS 的 `/` 或 Windows 的系统盘，不是所有挂载盘之和。`diskPath` 可以指定另一个路径。

累计流量为操作系统网卡累计计数，重启、网卡重建或切换接口后可能重置，不能作为服务商账单、3x-ui 用户计费或月流量账本。默认排除常见回环、Docker、veth、bridge 和 macOS utun 接口；存在 VPN、隧道或多网卡时，应明确配置真实出口 `networkInterface`，避免多接口重复计数。指定网卡不存在时明确报错，不会把配置错误显示成零流量。

TCP 延迟包括连接目标的握手耗时，不是 ICMP Ping。TCP 采样失败率只反映所选目标的 3 次尝试，不能等同于链路丢包率。未开启时页面显示 `-`。

## 3 免费额度与节点规模

截至核对官方文档时，Workers Free 每天 100,000 次动态请求，HTTP 和 Cron 每次 CPU 限额 10 ms。静态资源直出免费且不限请求次数。D1 Free 每天 5,000,000 行读取、100,000 行写入，账户总存储 5 GB，单数据库最多 500 MB，单次 Worker 最多 50 次数据库查询。批量请求不能代替查询总数控制。

免费额度是账户共享额度。超限后会报错或暂停相应请求，免费并不意味着无限可用，也不提供本项目的可用性保证。运行前应确认账号未开启会产生额外账单的付费服务。

设活动节点数为 N，实际最短上报间隔 R、历史间隔 H：

```text
R = max(管理员设置, ceil(N × 86400 / 35000 / 60) × 60)
H = max(管理员设置, R, ceil(N × 86400 × 4 / 20000 / 60) × 60)
离线阈值 = max(管理员设置, R × 3 + 60)
每日上报请求 ≈ N × 86400 / R
每日历史样本 ≈ N × 86400 / H
每日写入保守估算 ≈ 每日上报 × 2 + 每日历史样本 × 4
```

写入估算为最新节点更新、可能的索引开销、历史新增及到期删除预留空间，不是 Cloudflare 计费实测。告警、管理操作、登录限流和数据库维护会增加读写；应查看 D1 的 `rows_read` / `rows_written` 和控制台 Metrics。

使用默认设置时：

| 活动节点 | 实际上报 | 历史采样 | 日上报约 | 日写入估算约 | 7 天历史点约 |
| --- | --- | --- | --- | --- | --- |
| 20 | 120 秒 | 900 秒 | 14,400 | 36,480 | 13,440 |
| 24 | 120 秒 | 900 秒 | 17,280 | 43,776 | 16,128 |
| 50 | 180 秒 | 900 秒 | 24,000 | 67,200 | 33,600 |
| 100 | 300 秒 | 1,740 秒 | 28,800 | 77,462 | 34,759 |

每个整天打开概览的浏览器，在 120 秒间隔下增加约 720 个动态请求；节点数多时还会增加 D1 读取。历史图表访问会扫描所选节点的时间范围。大量公开访客或恶意请求可能耗尽免费额度，自动间隔保护只管理正常探针负载。多人长期观看、大量节点或需要秒级刷新时，应重新评估计划和架构。

建议先接 3–5 台，观察一天的实际写入量和 Workers CPU，再逐批加入 20 台以上。超过 100 台并非代码硬限制，但未完成该规模的线上持续压测，不应承诺长期免费稳定运行。缩短历史保留时间会集中触发一轮删除，首次清理也会消耗写入额度。

## 4 本地预览

在 `cf-vps-monitor` 目录执行，要求 Node.js 22.13 或以上版本：

```sh
npm ci
npm run setup:local
npm run build
npm run db:local
npm run seed:demo
npm run dev
```

浏览器打开 `http://127.0.0.1:5175`，点击管理员登录，使用 `.local-admin` 中的开发密钥。此文件和 `.dev.vars` 已忽略，不应上传 Git。

`seed:demo` 只写入本地 D1，包含 24 台虚构服务器，其中 1 台隐藏、1 台待接入、2 台初始离线。虚构在线节点没有持续探针，因此超过离线阈值后显示离线。这是正常状态判定，不是连接故障。请勿把演示节点当成真实服务器。

若 5175 或 8787 端口占用，可以在 `vite.config.ts` 和 `scripts/dev.mjs` 中配套修改端口、代理目标和本地 Origin 转换。部署脚本显式指定本项目的 `wrangler.jsonc`，避免误读父目录其他项目配置。

## 5 Cloudflare 正式部署

### 5.1 准备账户和数据库

需要一个 Cloudflare 账户和 Workers Free 计划。可直接使用 `workers.dev` 免费子域名，不必购买域名；自定义域名的注册费用不包含在 Cloudflare 免费托管中。

```sh
npm ci
npx wrangler login
npx wrangler whoami --config wrangler.jsonc
npx wrangler d1 create cf-vps-monitor --config wrangler.jsonc
```

登录在浏览器中完成。记录创建命令返回的 `database_id`，然后执行：

```sh
node scripts/prepare-deploy.mjs YOUR_DATABASE_ID
```

该脚本更新 `wrangler.jsonc` 中的 D1 绑定，并生成 `.production-secrets.json`，包含随机生成的 `ADMIN_PASSWORD` 和 `SESSION_SECRET`。文件权限默认仅当前用户可读写，不加入版本管理。不要复用开发密钥，也不要把生产密钥写进前端代码。

### 5.2 迁移和发布

```sh
npm run db:remote
npm run deploy
npx wrangler secret bulk .production-secrets.json --config wrangler.jsonc
```

首次部署前端后、Secrets 设置前，公开页为空站点，管理员接口返回未配置。设置完成后，用部署输出的 `https://...workers.dev` 地址访问站点，并使用生产 `ADMIN_PASSWORD` 登录。

请把生产密码存入自己的密码管理器。`SESSION_SECRET` 至少 32 字符，`ADMIN_PASSWORD` 至少 10 字符；生产环境仍推荐使用准备脚本生成的随机值。没有邮件找回密码功能，重置管理员密码需要 Cloudflare 的 Secrets 管理权限。

Cron `*/5 * * * *` 已写在配置中，发布后在 Workers 控制台确认已启用。Cloudflare 的计划任务更新可能需要一段传播时间。

### 5.3 自定义域名

在 Cloudflare Workers 控制台选中此 Worker，进入 Settings → Domains & Routes → Add → Custom Domain，填写自己管理的域名。配置完成后使用该 HTTPS 地址。

探针配置中的 endpoint 要使用最终可直达的域名，不能依赖 HTTP 重定向。探针禁止跟随重定向，避免 Authorization 密钥被转发到其他主机。更换域名后应更新探针配置并重启。

### 5.4 发布后的检查

1. 未登录时只能看到公开节点，隐藏节点的详情 API 也应拒绝访问。
2. 后台添加一台节点，下载专属 `config.json`。
3. 在节点上运行一次探针 `-once`，确认页面在线且出现历史样本。
4. 停止探针，等待离线阈值和下一轮 5 分钟 Cron，确认告警生成。
5. 启动探针，确认恢复事件。
6. 在 D1 Metrics 和 Workers Metrics 查看真实读写、请求和 CPU 用量。

当前交付尚未执行线上发布，原因是本机 Wrangler 没有 Cloudflare 登录状态。不是云端发布失败，也没有创建任何收费资源。

## 6 Linux 节点接入

推荐 Debian 11/12、Ubuntu 22.04/24.04 等使用 systemd 的系统。1 核 512 MB 或 1 GB 机器无需安装 Go 编译器，直接使用交付的静态二进制。

### 6.1 选择文件

执行 `uname -m` 检查架构：

| 输出 | 对应文件 |
| --- | --- |
| x86_64 | `cf-monitor-agent-linux-amd64` |
| aarch64 / arm64 | `cf-monitor-agent-linux-arm64` |
| i386 / i686 | `cf-monitor-agent-linux-386` |
| armv7l | `cf-monitor-agent-linux-arm` |

二进制使用 `CGO_ENABLED=0` 构建，不依赖节点上的 glibc 动态库。仍需系统 CA 证书和可访问站点的 DNS/HTTPS 网络。系统过旧时应检查 Go 运行时支持范围。

### 6.2 添加和安装

先在后台添加节点，下载 `config.json`。把对应二进制、配置、`agent/install-linux.sh` 和 `agent/cf-monitor.service` 放到服务器同一目录。建议通过自己的 SSH/SCP 工具传输，密钥不要放进聊天、公开仓库或 URL。

```sh
chmod +x cf-monitor-agent-linux-amd64
./cf-monitor-agent-linux-amd64 -config config.json -once
sudo sh install-linux.sh ./cf-monitor-agent-linux-amd64 ./config.json
systemctl status cf-monitor.service
```

安装脚本创建无登录权限的 `cf-monitor` 系统用户，二进制放在 `/opt/cf-monitor/`，私密配置放在 `/etc/cf-monitor/config.json`，权限为 root 与该服务组可读。服务无需 root 运行。更新配置后：

```sh
sudo systemctl restart cf-monitor.service
journalctl -u cf-monitor.service -n 30 --no-pager
systemctl show cf-monitor.service -p MemoryCurrent -p CPUUsageNSec -p TasksCurrent
```

部分较老 systemd 不支持个别限制指令，会在日志中提示；请确认服务启动成功。CPUQuota 是上限，采集较慢的机器可能因节流延迟启动。MemoryMax 64 MiB 是保护上限，出现 OOM 重启时先观察实际原因，不要直接取消限制。

Alpine/OpenRC、容器和其他服务管理器可以运行二进制，但附带 Linux 自动安装脚本仅支持 systemd。容器中看到的指标取决于可见的 `/proc` 和挂载路径，不能直接假设是宿主机指标。

### 6.3 与 3x-ui 共存

推荐只安装探针二进制，不在 512 MB 节点安装整套面板、Docker 或编译工具。默认关闭 `tcpProbe`；服务不开放新端口，不修改防火墙或 3x-ui 配置。

在 `config.json` 中将 `networkInterface` 指向实际公网出口，例如 `eth0` 或 `ens3`，避免隧道接口重复计数。接口名可以用 `ip -br link` 查看。修改后重启服务。

探针只观察系统，不负责限制 3x-ui 或其他业务的 CPU/内存。若节点已有内存压力，先把后台上报间隔设为 300 秒，再观察 `MemoryCurrent` 和日志。该配置不会改善业务程序本身的内存使用。

## 7 Windows 节点接入

提供 amd64 和 arm64 二进制。先在后台新增节点并下载配置，在 PowerShell 中进行单次上报：

```powershell
.\cf-monitor-agent-windows-amd64.exe -config .\config.json -once
```

使用管理员 PowerShell 安装自动启动任务：

```powershell
.\install-windows.ps1 -Binary .\cf-monitor-agent-windows-amd64.exe -Config .\config.json
Get-ScheduledTaskInfo CFMonitor
```

安装器放置文件到 `%ProgramData%\CFMonitor`，限制目录访问，使用低权限 LocalService 账户运行计划任务，开机启动、失败有限重试。任务不是 Windows 原生 Service Control Manager 服务。若 PowerShell 执行策略阻止脚本，请按你自己的系统策略审查和允许运行本地脚本，不需要全局关闭安全策略。

默认采集系统盘，例如 `C:\`；可在配置中设置其他盘路径。部分环境下性能计数器和目录访问受系统策略影响，需要检查任务运行结果。当前已完成 Windows 两个架构编译和 CI 工作流配置，尚未在真实 Windows 机器执行安装与常驻验收。

## 8 macOS 节点接入

Apple Silicon 使用 darwin-arm64，Intel Mac 使用 darwin-amd64。先做单次采集：

```sh
chmod +x cf-monitor-agent-darwin-arm64
./cf-monitor-agent-darwin-arm64 -config config.json -once
sh install-macos.sh ./cf-monitor-agent-darwin-arm64 ./config.json
launchctl print gui/$(id -u)/com.cfmonitor.agent
```

macOS 安装器不使用 sudo，创建当前用户的 LaunchAgent，文件放在 `~/Library/Application Support/CFMonitor/`。它在用户登录时运行；注销或系统休眠时可能停止上报，面板按阈值判定离线。无人登录也需持续监控的场景要单独配置系统级 LaunchDaemon。

交付文件未进行 Apple 开发者签名或公证。下载后若被系统阻止，请按 macOS 的正常软件审核流程处理，不应绕过未知来源程序警告。当前本机 Apple Silicon 已验证真实指标采集、上报和历史保存；自动登录启动脚本未在本机安装，避免改变用户的系统启动项。

## 9 配置字段

```json
{
  "endpoint": "https://your-monitor.example.com",
  "token": "cvm_独立节点密钥",
  "interval": 120,
  "diskPath": "/",
  "networkInterface": "eth0",
  "tcpProbe": "",
  "probeEvery": 5
}
```

| 字段 | 说明 |
| --- | --- |
| endpoint | 站点 HTTPS origin，不带路径、查询或账号密码；只允许 localhost 使用 HTTP |
| token | 后台生成的独立探针密钥，数据库只保存 SHA256 摘要 |
| interval | 启动默认间隔 60–3600 秒；成功响应或 429 中的后端间隔会覆盖它 |
| diskPath | 监测的一个文件系统路径，留空使用系统盘 |
| networkInterface | 指定一个网卡名；留空汇总经过过滤的接口 |
| tcpProbe | 可选 `host:port`，默认关闭，IPv6 使用 `[地址]:端口` |
| probeEvery | 每多少个上报周期执行一次 TCP 采样，1–60，默认 5 |

后台“上报间隔”是集群级设置。节点扩大后后端自动提高有效间隔和离线阈值，探针下次收到响应时采用新间隔。后台分别保留管理员设置与当前规模下的有效值，保存设置不会把自动保护值固化；减少节点后可回到原先的间隔。`-print` 只打印采集 JSON 不上报；`-once` 采集并上报一次后退出；`-version` 显示版本。配置有严格字段校验，未知字段会报错。

## 10 后台日常管理

“运行概览”向管理员显示所有活动节点的完整指标和地图。游客仅看到公开节点的匿名编号及正常、异常、离线、待接入状态；卡片跳转到独立匿名状态页。真实名称、IP（包括填写在名称或备注中的地址）、地区、坐标、系统、硬件、费用与历史指标均不由公开接口返回。公开编号使用服务端 SESSION_SECRET 进行 HMAC 派生，不使用真实节点 ID；需配置至少 32 字符的密钥。“节点管理”支持编辑名称、区域、分组、价格、周期、日期、备注和权重。较小的排序权重排在前面。

新增节点只创建元数据记录，没有模拟硬件指标。CPU、内存、磁盘、系统与流量均在探针上报后取得。名称、地区、分组与费用为管理员记录，不自动反推真实地理位置或服务商账单。“费用与更多信息”为可折叠的选填部分。

接入弹窗按 Linux、Windows、macOS 架构给出对应二进制文件名与单次检查命令，允许明确填写出口网卡和磁盘路径。收到比弹窗打开前更新的有效样本后显示“已收到真实上报”。本地预览地址无法用于远程 VPS，本地节点密钥也不存在于生产数据库，因此本地预览禁止下载远程配置；必须在正式 HTTPS 站点重新创建节点。

概览按“全部、在线、离线、待接入”筛选。离线节点的 CPU、内存使用率、磁盘使用率与网速显示 `-`，保留最近上报时间和已知硬件总量。详情中的历史指标以“最后有效样本”及时间标记，不等于当前机器状态。

创建节点或重置密钥时，只展示一次明文密钥，并可下载配置文件。已有密钥不能从后台再次查看；丢失后需要重置。重置立即撤销旧密钥，相关探针需要更新配置并重启。

归档节点是可恢复删除。它立即停止接收数据，探针会收到 401；Linux/Windows 服务管理器重试有限次数后停止，macOS LaunchAgent 会间隔重试，应同时停止对应启动项。恢复节点后状态回到“待接入”，原密钥仍有效，需重新启动探针。旧历史在保留期限内仍存储，但归档状态不提供详情访问。

“费用与到期”按币种分别汇总月均费用，没有自动汇率转换。季付除以 3，年付除以 12，免费节点不计费用。金额与到期日期由管理员手工维护，不连接服务商账单。日期按 UTC 日结束判定。

“导出配置”导出站点设置和节点摘要，不包含明文探针密钥、会话 Secret 或完整历史。当前未提供网页导入；完整灾备需要 D1 数据库备份，见后文。

## 11 告警与 Telegram

默认每 5 分钟检查活动节点的离线、CPU、内存、磁盘和到期状态，仅在状态发生变化时生成事件，解除异常时生成恢复记录。同一状态不持续刷屏。新建但从未上报的节点显示待接入，不产生离线告警。

这是对最近一次低频样本的判断，不是持续时间窗口告警。如果 CPU 在某次采样后短时恢复，可能在下一轮 Cron 前被覆盖；需要高精度告警时应调整采样策略和免费额度预期。

Telegram 在 Cloudflare Secrets 中配置，后台只显示是否已配置，避免把机器人密钥返回浏览器：

```sh
npx wrangler secret put TELEGRAM_BOT_TOKEN --config wrangler.jsonc
npx wrangler secret put TELEGRAM_CHAT_ID --config wrangler.jsonc
```

机器人需要能向目标聊天发送消息。启用后，节点名称、站点名称和异常描述会发送到你指定的 Telegram 聊天，请选择合适的接收范围。后台全局告警开关关闭后不发送通知。

每次 Cron 最多投递 5 条，失败保留队列下次重试，仅重试最近 24 小时事件。数据库记录保留 30 天。外部发送成功但本地标记失败时可能重复投递，因此不是严格“恰好一次”交付。大量同时异常可能排队；通知不可替代独立的紧急告警系统。

当前无 Telegram 机器人凭据，已验证事件生成与恢复，没有发送真实 Telegram 消息。

## 12 安全与备份

管理登录使用随机密钥，12 小时签名会话，HttpOnly、SameSite=Strict，生产 HTTPS 下设置 Secure Cookie。后台写入检查请求来源和登录身份。探针令牌只授权本节点上报，不具备后台管理权限。SQL 参数化，JSON 请求限制 16 KiB，指标范围严格校验。

登录按 IP 的 15 分钟窗口限制最多 10 次尝试。失败时不要反复提交，等待窗口重置。该机制仍消耗少量 D1 写入；有公开流量风险时可结合 Cloudflare 访问控制策略保护管理入口，但不要把探针 API 一并阻断。

管理员登录密钥没有多用户或密码找回机制。更换 ADMIN_PASSWORD 后，为使所有现有会话立即失效，应同时轮换 SESSION_SECRET：

```sh
npx wrangler secret put ADMIN_PASSWORD --config wrangler.jsonc
npx wrangler secret put SESSION_SECRET --config wrangler.jsonc
```

完整数据库备份：

```sh
npx wrangler d1 export DB --remote --config wrangler.jsonc --output monitor-backup.sql
```

备份包含节点元数据、探针令牌摘要、监控历史和事件，应按私密文件保存。恢复前创建独立数据库，在其配置绑定下导入备份并验证，再切换生产绑定；不要直接对已有生产库执行未知 SQL。Cloudflare Secrets 不在 D1 备份中，需要单独保管。

不要提交 `.dev.vars`、`.local-admin`、`.production-secrets.json`、实际节点 `config.json` 或私密备份。项目打包脚本按允许列表包含源码、公开资源、文档和探针二进制，排除开发数据库和私密文件。

## 13 升级和卸载

### 面板升级

先备份 D1 和 Secrets。更新源码后运行 `npm ci`、`npm run check`、`npm test`、`npm run build`。存在新增迁移时先阅读迁移内容，再执行 `npm run db:remote`；最后 `npm run deploy`。前端和后端作为同一个 Worker 发布。

### 探针升级

在开发机编译或使用已交付的架构文件，不在 512 MB VPS 上现场编译。核对 `SHA256SUMS` 后替换二进制并重启，保留原有 `config.json`。Linux 安装脚本会先停止正在运行的服务，再复制新文件。

### 停止和卸载

Linux：

```sh
sudo systemctl disable --now cf-monitor.service
sudo rm /etc/systemd/system/cf-monitor.service
sudo systemctl daemon-reload
```

确认无需回滚且已备份配置后，可自行删除 `/opt/cf-monitor/`、`/etc/cf-monitor/` 和服务账户；后台把节点归档即可停止监控。

Windows：

```powershell
Stop-ScheduledTask -TaskName CFMonitor
Unregister-ScheduledTask -TaskName CFMonitor
```

确认后删除 `%ProgramData%\CFMonitor`。macOS：

```sh
launchctl bootout gui/$(id -u)/com.cfmonitor.agent
```

然后删除对应 LaunchAgent plist 和应用目录。上述删除步骤由使用者在确认不再需要后执行，安装程序不会自动清除历史文件。

## 14 常见故障

| 现象 | 排查方向 |
| --- | --- |
| 管理员接口 503 | Secrets 尚未设置、长度不足、D1 未迁移或额度耗尽 |
| 登录返回 401 | 管理员密钥错误；开发和生产密钥不能混用 |
| 登录返回 429 | 同 IP 登录次数超过 15 分钟窗口限制 |
| 探针返回 401 | 节点密钥错误、已经轮换或节点已归档 |
| 探针返回 429 | 上报过快；探针会采纳服务端间隔后重试 |
| 长期待接入 | 未启动探针、URL 不可达、证书/DNS/配置错误 |
| 周期性离线 | 机器休眠、业务负载、网络超时或离线阈值太小 |
| 历史没有秒级变化 | 默认低频采样设计，15 分钟保留一个样本 |
| 流量与 3x-ui 不一致 | 系统网卡统计与用户业务计费口径不同，检查出口接口 |
| TCP 指标为空 | 默认关闭探测，或所有连接尝试失败时没有延迟样本 |
| Telegram 未送达 | Bot/Chat Secret、聊天授权、外部网络、待投递队列 |
| 网站突然全部报错 | Workers/D1 日额度、CPU 限额或 Cloudflare 状态 |
| Linux 服务 OOM | 查看 MemoryCurrent、系统日志和服务内存上限 |
| 中国大陆无法访问 workers.dev | 网络可达性由本地网络与域名决定；自定义域名也不能保证所有网络可用 |
